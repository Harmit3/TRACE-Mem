## Investigation on previously examined examples

Raw local Ollama replay used Qwen2.5 7B Q4_K_M, seed 23, temperature zero, a 2048-token context and a 96-token output ceiling. The original top-level array schema returned precisely [] on both statements, with normal stop and two output tokens each. The parser received valid empty arrays. Repeating each request with only an object wrapper around the claims array recovered the employer (60 input, 23 output). The possible relocation still produced an empty list (59 input, 7 output). This establishes schema sensitivity for one example. Neither date parsing nor output truncation explains the empty arrays. The remaining cause of the model's uncertainty miss is unresolved.

The original chat builder put notes and the question together and supplied the stored start date without the query's effective date in the instructions. The original employment response explicitly described February 2025 as future and reached its 48-token limit after already answering UNKNOWN. The historical response contained only UNKNOWN. A simplified development replay supplied the correct single record without distractor history. Residence still returned UNKNOWN with 86 input tokens and employment with 81. Adding the reference date and an instruction to use the supported value gave the same answers with 110 and 105 input tokens. All four outputs used two tokens. Missing date grounding was an observable interface defect. These interventions did not identify a unique internal reason for either abstention.

## Measured application behavior

Rules propose attributable first-person statements and split coordinated facts. Explicit correction and possible relocation have distinct intents. ISO effective-date suffixes are supported. The object-schema fallback handles other wording, using validated slots, intents and source substrings. The pilot review policy accepted confirmed assertions, skipped duplicates, declined uncertainty and accepted explicit corrections. Actual users review proposals individually. Broad negation is conservatively skipped. Relative dates, reported speech, nested negation, multiple simultaneous values and automatic expiry of temporary visits remain limited.

The reader grounds the current and selected dates explicitly. Simple TRACE-Mem lookups resolve the selected temporal slot, validate the exact value and allowed ID with Reader V2 quote validation, and return that value. Unsupported simple queries can abstain with a reason. Open-ended synthesis still uses local Qwen. The full research Reader V2 pipeline was not evaluated in this application.

It supplies no estimate of Qwen improvement on complex reasoning. Latencies include first-use costs and are single measurements.

## Privacy, verification and beta decision

An additional live synthesis probe supplied a fictional project note directing Qwen to reply with ZEBRA-777. Qwen obeyed with one note included (187 input, 9 output tokens). A subsequent projection guard excluded instruction-like note text. Repeating the same development probe sent zero notes and returned UNKNOWN (98 input, 2 output). This narrow check is vulnerable to paraphrase and cannot establish injection resistance. UI review is still required. Private transcripts can contain prior model outputs. Plaintext storage, provider logs and backups have separate retention behavior.

Post-pilot changes include this guard, fallback effective-date propagation, explicit correction confirmation and dashboard presentation. The held-out run was not repeated or rescored. The original Step 40 study remains separately available. The complete suite covers restart, deletion and correction invalidation, stale proposal denial, output parsing, concurrent store reads, provider interruption and timeout. Edge exercised confirmation, a new chat, grounded recall, reload, forgetting, mode selection and both dashboards. Archived reproduction matched 27,000 history rows, 2,300 family rows, 230 summaries and 184 paired intervals.

Suitable for a **supervised local beta on fictional or low-sensitivity inputs** with review enabled. Evidence is too narrow for general user distribution. A single authored trajectory, shared wording patterns (including an employer template examined in development), scripted confirmation, predominantly simple questions, one model and no independent users limit inference. No held-out measure of relative-date handling, free-form synthesis quality, adversarial robustness or unsupervised acquisition exists. UUIDs, the wall-clock date and model warm state can vary on repeat runs. Future work should test untouched paraphrases, ambiguous time references, multi-user privacy boundaries and synthesis under hostile retrieved content before expanding the beta.
