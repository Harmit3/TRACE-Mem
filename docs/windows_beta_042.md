## Retrieval, synthesis and model failure

The Step 41 ZIP includes an isolated standard-library Python runtime. It excludes the scientific Python stack and model assets, and its desktop host explicitly disabled semantic ranking. The existing Llama generation model returned HTTP 501 to a local embedding request during development. In 0.42.0 the optional MiniLM worker uses the already-installed Windows Python 3.14 interpreter under Program Files, PyTorch, Transformers and the cached safetensors checkpoint pinned in the pilot. It runs on two CPU threads, processes small batches over local pipes, and disables model downloads. No weights or tensor runtimes are redistributed. The inspector shows retrieval status. An absent or failed encoder falls back to the lexical ranker, while recognized exact questions can use direct lookup. A backend restart re-enables a failed worker. Only trusted locally installed Python packages should be used. The four paraphrase probes yielded one top-one hit with MiniLM and none with lexical search.

Newly reviewed structured fields can include bounded project counts, durations, capacities, budgets and ISO deadlines. Short title-case residence, job and education values remain usable in the application. Generated synthesis represents named values as opaque references and resolves recognized references locally for display. Turns containing resolved names stay outside subsequent generation context. Explicitly approved numeric/date values can reach the local generation model. The label grammar, numeric bounds, calendar parsing, source IDs and authoritative store lookup constrain what can enter a prompt. RAG receives retained versions only under a new explicit revision grant. Older grants stay current-only. Missing authorization, expired rows and forgotten IDs are checked before projection. A saved value can still be factually wrong; typed evidence and local alias resolution cannot establish its truth or general injection resistance. Direct user messages and display data still require care.

## Profile migration and readiness

Packaged chat titles, user messages and assistant replies use current-user Windows DPAPI. A protected desktop startup encrypts prior content and updates the SQLite schema to v3 in a transaction. An earlier beta cannot open the upgraded chat database. Keep any necessary backup under the same user's control before upgrade. Old backups may retain plaintext or forgotten information. SQLite still exposes identifiers, row sizes and structural metadata. DPAPI cannot protect a running unlocked session from same-user programs or guarantee forensic erasure. Source-mode developer databases retain their prior behavior unless protection is explicitly enabled. Searches decrypt candidate content locally and can take longer on large profiles.
