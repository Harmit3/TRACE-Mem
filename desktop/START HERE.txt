TRACE-Mem Workspace • Supervised Windows beta 0.42.2

1. Right-click the ZIP and choose Extract All. Choose a folder in your Windows profile.
2. Open TRACE-Mem Workspace.exe. Keep its small launcher window open while using the browser. The browser opens a private loopback address on an available port.
3. Try sample memories and the offline lookup. For generated answers, start the Ollama desktop application with a locally installed model, then refresh Workspace. The model picker lists available tags. No model downloads are automatic. Select Qwen2.5 7B Instruct for these pilot tasks or Llama 3.2 3B for less GPU memory.
4. To stop, close the launcher. Closing only the browser leaves the backend running. The launcher can reopen the browser. Create shortcuts is optional.
5. Use low-sensitivity or fictional information. Review each suggested memory before saving it. Forget removes all saved versions of a label and blocks earlier turns from future model context. Delete chats separately to remove their visible transcript.
6. Direct lookup returns a current or selected historical field. Explicit sharing supports project A–Z duration minutes, sessions, capacity, budget dollars and ISO deadlines, plus short title-case residence, job and education values. RAG may see retained versions only with the new grant. Check the evidence inspector. Other saved text is available for reviewed lookup. Recent eligible user chat messages still reach the model. Optional semantic search runs a local CPU MiniLM worker if Python 3.14, torch, transformers and the pinned checkpoint are already available on the machine. Otherwise exact and lexical lookup remain available. No embeddings or model weights are bundled.
7. Records are under %LOCALAPPDATA%\TRACE-Mem Beta. Windows restricts this directory to your account. Memory snapshots use Windows current-user DPAPI. Packaged chat titles, questions and replies also use DPAPI. SQLite metadata and older copies can still be visible. Same-user apps, administrators, backups, screenshots, browser sessions, disk recovery and Ollama logs can retain information. A false note you approved can produce a false answer.
8. On upgrade, close the old launcher, extract the new ZIP to a new folder and launch it. The same beta profile reopens. An old plaintext memory snapshot already in the beta profile is validated and encrypted atomically at startup. Version-1 and version-2 databases migrate transactionally to version 3; old transcripts stay visible and are excluded from future prompts. The source checkout's separate profile is never imported automatically.
9. If the runtime fails, extract the entire archive again, check free space, and ensure 64-bit Windows, .NET Framework 4.x and the Microsoft VC++ x64 runtime are available. If a profile cannot be opened, close other running copies. New recovery profile starts a separate empty profile and preserves the original. Restore a known-good backup only after reviewing its deletion history.
10. To uninstall, stop the launcher, delete the extracted folder and its two optional shortcuts. Your data stays in the profile folder. Delete that folder separately only if you intend to remove all local beta profiles. Ollama and models are installed separately.

Open practice profile in the launcher for an isolated fictional rehearsal. The practice guide contains two sample personas and an optional unsaved scratchpad. Close all prior launchers before upgrading. Older beta versions cannot read upgraded transcripts.
